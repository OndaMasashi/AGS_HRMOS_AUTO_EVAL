System Overview

HRMOS採用
応募者書類 AI自動評価ツール

応募者の履歴書・職務経歴書を自動で取得し、あらかじめ決めた評価基準でAIが採点して、 Excel の一覧表にまとめます。書類選考の下ごしらえを、1コマンドで終わらせるための道具です。

1実行はコマンド1つ
3形式PDF / Word / Excel
1–5点評価項目ごとの採点
3.9秒1名あたり評価時間
0.8円1名あたり費用

※ 評価時間と費用は Gemini（gemini-3.5-flash-lite）を使った場合の実測値です。Claude を選んだ場合の費用は契約中のプランに含まれます。

Part 1

機能 — 何ができるか

採用担当者の目線での説明です。技術的な内部構造は第2部で扱います。

何をするツールか

これまで人が1件ずつ開いて読んでいた応募書類を、ツールが代わりに集めて読み、 評価基準ごとに点数とコメントを付けます。担当者は出来上がった一覧表を見て判断するところから始められます。

書類の自動取得

HRMOS採用にログインし、応募者一覧から添付書類（PDF / Word / Excel）をまとめてダウンロードします。「さらに表示」も自動でクリックし、全件を取りこぼしません。

評価基準ごとの採点

設定した項目それぞれに1〜5点を付け、その点数の根拠となるコメントを書きます。点の付け方の物差し（ルーブリック）をAIに明示しているため、応募者間のばらつきを抑えています。

面接質問の自動生成

その応募者の書類内容に即した質問を3つ作ります。「何を確かめたいか」の観点も設定で指定できます。

1次通過候補の判定

年齢帯ごとに平均点のしきい値を決めておくと、○ / △ で候補を絞り込みます。若手とベテランで同じ物差しにならないようにするためです。

Excel 一覧表の出力

1行＝1応募者。総合ランクは色分けされ、評価項目のバランスはレーダーチャートで一目で分かります。

メール通知

評価が終わるとサマリと Excel が届きます。新規0件のときも「新規なし」を通知するため、無音＝失敗の見逃しが起きません。

前回の続きから動きます

評価済みの応募者は自動的に飛ばされ、新しく応募してきた人だけが処理されます。毎日実行しても同じ人を再評価してコストを使うことはありません。

最終判断は必ず人が

AI の評価は参考情報です。採用選考でのAI利用は、有資格者による事前レビューが利用規約上の要件になっています。AIの点数だけで足切りする運用にはしないでください。

HRMOS へ自動で NG 評価を登録する機能もありますが、初期状態では無効です。有効にすると人が書類を見ないまま不合格が確定するため、採用責任者の承認と、登録済みの応募者を人が抜き取り確認する運用が前提になります。

処理の流れ

run_scan.bat をダブルクリックすると、次の6段が順に走ります。途中で人が操作する場面はありません。

AIに渡るもの・課金されるタイミング

外部のAIと通信するのは、上の図の 5「AI評価」だけです。 それ以外の段はすべてPC内とHRMOSの間で完結します。

コマンドAIを呼ぶか費用
run.py scan呼ぶ（新規の応募者ごとに1回）1名あたり約0.8円
run.py scan --all呼ぶ（登録済み全員ぶん）人数 × 約0.8円
run.py report呼ばない0円
run.py status呼ばない0円
run.py doctor呼ぶ（疎通確認で1回だけ）ごく僅か
run.py doctor --skip-llm呼ばない0円

AIに送られるのは 書類から取り出した文章（個人情報を伏せたもの）・ 評価基準・面接質問の観点 の3つだけです。 PDF等のファイルそのもの、HRMOSのログイン情報、データベースの中身は送信されません。 設定ファイルを編集しただけでは課金は発生しません。

送信前に個人情報を伏せます

AI に渡す直前に、氏名・電話番号・住所を目印（プレースホルダ）に置き換え、返ってきた文章の中で元に戻しています。ただし職歴・所属企業名・資格は伏せていません（評価に必要なため）。

出力される成果物

Excel 一覧表

1行＝1応募者。左から順に、まず判断に効く要約が並び、右へ行くほど詳細になります。

メール通知（任意）

評価サマリ表と Excel が届きます。表の「○」は HRMOS の応募者ページへのリンクになっており、そのままクリックで開けます。1次通過候補の経歴書を添付することもできます（個人情報を含むため、社内ポリシーを確認のうえで）。

送られるのは次の3種類です。いずれの場合も必ず何かが届くため、届かない＝異常と判断できます。

  • 評価結果メール — 新規応募者を1名以上評価できたとき
  • 「新規なし」通知 — 新規0名で正常に終わったとき
  • 失敗アラート — 認証失敗・一覧0件・評価成功0件・処理中の例外

評価基準の設定

評価項目は config.yaml で自由に決められます。項目名と、AIに伝える「何を見るか」の説明を書くだけです。

evaluation_criteria:
  - name: "プログラミング経験"
    description: "IT開発工程における開発経験（Python, JavaScript 等）の経験と深さ"
  - name: "マネジメント経験"
    description: "チームリーダー、プロジェクトマネジメント等の経験の有無と深さ"

first_pass_criteria:          # 1次通過候補の判定（年齢帯ごとの平均点しきい値）
  - age_range: [25, 29]
    min_avg_score: 2.4        # これ以上で○、0.3 点手前まで△

description を具体的に書くほど評価が安定します。項目数に制限はありませんが、増やすほど1件あたりの処理時間と費用が伸びます。

評価基準を変えたら

過去に評価した人と新しい人で物差しが変わります。過去分と比較したい場合は run.py scan --all で全員を再評価できますが、登録済みの応募者全員に対して HRMOS へのアクセスと AI 呼び出しが発生します。件数によっては数時間かかるため、実行前に run.py status で対象数を確認してください。

運用と自動実行

コマンド内容使いどころ
run.py scan新規応募者をAI評価し、Excelを出力日常はこれだけ
run.py scan --all全応募者を再評価評価基準を変えたとき
run.py reportDBの過去分をExcelに再出力（評価はしない）過去データの出し直し
run.py status評価の進捗を表示状況確認
run.py doctor環境を10項目で自己診断導入直後・不調のとき

平日 12:30 と 17:30 の自動実行を Windows のタスクスケジューラに登録できます（setup\setup_scheduler.bat）。 管理者権限は不要で、スリープからの復帰後に取りこぼしを実行する設定も同時に入ります。

Part 2

構造 — どう作られているか

保守・引き継ぎのための技術説明です。

レイヤー構成

run.py が入り口、src/main.py が全体の進行役です。 main が5つのレイヤーを順に呼び出し、レイヤー同士は直接やり取りしません。 そのため1つのレイヤーを差し替えても他に波及しません（AI を Claude から Gemini へ替えられたのはこの構造のためです）。

AI評価の仕組み

書類のテキストと評価基準からプロンプトを組み立て、AI に送り、返ってきた JSON を検証して保存します。 AI との接点はこの1箇所だけで、他のレイヤーは AI の存在を知りません。

データモデル

SQLite に4つのテーブルを持ちます。評価結果は1応募者 × 評価基準の数だけ行が入る形です。

エラー処理の方針

1人の失敗で全体を止めないのが基本方針です。失敗した応募者は記録に残し、残りの処理は続行します。

発生箇所種類動作
browser/authログイン失敗処理中断＋失敗アラート送信。セッション失効は自動で再ログイン
browser/navigator要素が見つからないその応募者をスキップし警告ログ
browser/page_utilsページ遷移の失敗最大3回まで再試行
parser/document解析失敗空テキストを返し、その応募者をスキップ
evaluatorタイムアウト / API エラー最大3回リトライ後スキップ（status='error'）
evaluatorJSONパース失敗同上
reporter/notifyメール送信失敗ログのみ。評価結果には影響しない
無音で失敗しない設計

一覧が0件だったときは画面と HTML を data/debug/ に保存します。ログイン画面が写っていればセッション要因、一覧の構造が変わっていれば HRMOS の UI 変更（selectors.py の見直し）と切り分けられます。

認証情報の置き場所

インストーラで入力した認証情報は config.yaml ではなく Windows のユーザー環境変数に保存されます。フォルダごとコピーしても認証情報が一緒に持ち出されないようにするためです。

環境変数上書きする設定
HRMOS_EMAILcredentials.email
HRMOS_PASSWORDcredentials.password
GEMINI_API_KEYevaluation.gemini_api_key
RESEND_API_KEYemail.api_key
機密として扱うファイル

storage_state.json は HRMOS のログイン済みセッションです。これを持っているだけでパスワード無しでログインできてしまうため、配布物やバックアップに混入させないでください（配布zipの作成スクリプトは自動で除外します）。

HRMOS採用 応募者書類AI評価ツール — 全体像。 導入手順は同梱の SETUP_GUIDE.html、設定の変更は SETUP_GUIDE.ADVANCED.html、設定項目の全一覧は config.yaml.example のコメントを参照してください。
