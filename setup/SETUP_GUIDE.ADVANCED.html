Configuration Guide

評価の中身を変える

評価項目・面接質問・1次通過ラインは、config.yaml をメモ帳で編集するだけで変えられます。 やりたいことを下から選んでください。

編集するファイル config.yaml
ツールのフォルダ直下（run.py と同じ場所）
始める前に コピーを取って config.yaml.backup として残す
保存は上書きのみ Ctrl+S を使う。「名前を付けて保存」は .txt が付いて反映されません
評価項目を増やしたい「英語力」など新しい観点を足す 評価項目を減らしたい使っていない観点を外す 点の付け方を変えたい評価が甘い／辛いと感じるとき 1次通過候補の数を調整したい○が多すぎる／少なすぎる 面接質問を変えたい質問の観点や数を指定する 過去の人も評価し直したい基準を変えた後、物差しを揃える メールの宛先を増やしたい通知を受け取る人を追加する 経歴書の添付をやめたいメールに個人情報を載せない ブラウザを表示したくない裏で静かに実行する 保存したら動かなくなったエラーの読み方と元に戻す手順

手順

1評価項目を増やしたい

evaluation_criteria: の一番下に、2行セットで追加します。既存の行をコピーして中身を書き換えるのが確実です。

evaluation_criteria:
  - name: "自己学習・成長意欲"
    description: "自己学習として業務以外で何か意欲的に..."
  - name: "英語力"
    description: "TOEICスコア、海外案件の経験、英語での業務経験の有無と深さ"

name が Excel の列名、description が AI への指示です。項目数に上限はありません。

書類に書かれていないことは評価できません

AI が見るのは提出書類だけです。「人柄」「熱意」のように書類に痕跡が残らないものを項目にすると、ほぼ全員が最低点になります。

2評価項目を減らしたい

その項目の 2行をまとめて削除します。name だけ消して description を残すとエラーになります。

× 片方だけ消した
  - name: "設計経験"
    description: "IT開発の上流工程..."
    description: "資格の有無..."
✓ 2行セットで消す
  - name: "設計経験"
    description: "IT開発の上流工程..."

最低1項目は必要です。全部消すと動きません。

3点の付け方を変えたい

点数を決めているのは description です。「何を見るか」に加えて「どういう場合に下げるか」まで書くと、応募者ごとのばらつきが減ります。

× 判断がぶれる
- name: "コミュニケーション力"
  description: "コミュニケーション能力"
✓ 判断が安定する
- name: "コミュニケーション力"
  description: "顧客折衝・社内調整の経験。
    提案や合意形成を主導した記述があれば
    高く評価する。担当作業の記述のみで
    対人の役割が読み取れない場合は下げる"

全項目に共通で効かせたい指示は evaluation.system_instructions に書きます（例:「書類に明記された事実のみを根拠にする」）。

41次通過候補の数を調整したい

年齢帯ごとに「平均点が何点以上なら ○ にするか」を決めています。0.2〜0.3 ずつ動かして調整してください。

first_pass_criteria:
  - age_range: [25, 29]
    min_avg_score: 2.4   # 下げると○が増える / 上げると減る
平均点判定
min_avg_score 以上○（候補。メール通知にも載る）
その 0.3 点手前まで△（目視で確認したい層）
それ未満空欄
再評価は不要です

これは線引きを変えるだけなので、run.py report で Excel を出し直せば既存の評価にすぐ反映されます。AIの費用もかかりません。

空欄になる2つのケース

どの age_range にも入らない年齢（例: 55歳以上）と、書類から年齢を読み取れなかった応募者は、点数に関わらず空欄になります。対象を広げたいときは年齢帯の行を追加してください。

5面接質問を変えたい

count が質問の数、perspective が「何を確かめたいか」です。中身は普通の日本語で構いません。

interview_questions:
  count: 3
  perspective: |
    応募者の自律性や自己成長意欲を確認する質問。
    35歳以上であれば、マネジメント面の素養を問う質問。

| は「次の行から複数行が続く」という印です。各行の行頭の空白は揃えてください。count を変えると Excel の質問候補の列数も変わります。

6過去の応募者も評価し直したい

評価項目を変えても、評価済みの人は自動では変わりません

これ以降に評価される人だけが新しい基準になるため、同じ Excel に古い基準の人と新しい基準の人が混在します。物差しを揃えるには全員の再評価が必要です。

まず対象が何人いるかを確認します。

.venv\Scripts\python.exe run.py status

そのうえで全員を再評価します。

.venv\Scripts\python.exe run.py scan --all
実行前に

登録済みの応募者を全員もう一度処理します。件数によっては数時間かかり、HRMOS へも同じ回数アクセスします。AI の利用料も人数分かかります。終業後や休日に実行してください。

7メールの宛先を増やしたい

email:
  to:
    - "saiyo@example.com"
    - "bucho@example.com"

- の前の空白は上の行と同じだけ空けてください。メール通知をまだ有効にしていない場合は、導入ガイドのメール通知の章を先に済ませてください。

宛先を増やす前に

attach_resumes: true のままだと、経歴書も宛先全員に届きます（次項）。

8経歴書の添付をやめたい

email:
  attach_resumes: false   # true だと1次通過候補(○)の経歴書が添付される
添付される経歴書は伏字ではありません

AI に送るときだけ氏名・電話・住所を伏字にしており、原本には手を加えていません。宛先を増やすほど個人情報が渡る範囲も広がります。社内の取り扱いルールを確認して判断してください。

9ブラウザを表示したくない

scan:
  headless: true    # true で画面を出さずに裏で実行する

自動実行にしている場合は true が向いています。うまく動かないときの原因調査には false にして画面を見るのが有効です。

触らない方がよい項目

wait_between_pages（既定 2秒）は HRMOS への負荷を抑えるための待ち時間です。短くしないでください。

保存したら動かなくなったとき

まず、どこが悪いかを確認します。AI は呼ばないので費用はかかりません。

.venv\Scripts\python.exe run.py doctor --skip-llm
表示されるメッセージ原因
YAMLとして読めません行頭の空白がずれているか、全角スペースが混ざっている。行番号が出るのでその付近を確認
N 番目に name と description が必要です項目を消したときに片方だけ残っている
evaluation_criteria が未設定です項目を全部消してしまっている（最低1つ必要）
内容が空ですファイルが空になっている

崩れやすい3か所

原因対処
行頭の空白元の行と同じ数だけ字下げする。増減させない
全角スペース字下げするときは日本語入力をオフ（半角/全角）にする
引用符の閉じ忘れ説明文は必ず " で囲む。: や # を含む文は囲まないと途中で切れる

元に戻す

バックアップがある場合は、それを config.yaml に戻すだけです。ない場合は次の手順で作り直せます。

  1. 壊れた config.yaml の名前を config.yaml.broken に変える（消さない）
  2. config.yaml.example をコピーし、名前を config.yaml にする
  3. setup\install.bat を実行し直す（AIの設定が書き戻ります）
  4. 壊れたファイルを見ながら、自分の変更を少しずつ入れ直す
評価済みのデータは消えません

config.yaml を作り直しても、これまでの評価結果は別ファイルに保存されているため残ります。
