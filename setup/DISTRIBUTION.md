# 配布手順書（配る側）

同僚へツールを配布するときの手順です。受け取る側の手順は [SETUP_GUIDE.html](SETUP_GUIDE.html) を参照。

---

## 配布前に済ませておくこと

### 0. AI をどちらにするか（配布先ごとに選べます）

インストーラの途中で、受け取る側が **Gemini / Claude** を選べます。人によって違っていても構いません。

| | Gemini（APIキー） | Claude（サブスクリプション） |
|---|---|---|
| 費用 | 使った分だけ。1名あたり約0.8円 | **契約中のプランに含まれる。追加請求なし** |
| 必要なもの | 課金が有効なAPIキー | Pro / Max / Team / Enterprise 契約 |
| 事前準備 | APIキーの発行と課金設定 | なし（インストーラが Claude Code を自動導入） |
| 導入時の手作業 | キーを貼り付けるだけ | **初回1度だけブラウザでログイン** |
| 複数人での共有 | キーの共有は可能 | **契約の共有は規約違反** |
| 無人実行の安定性 | 高い | ログイン状態が切れると止まる |

**使い分けの目安**: すでに Claude を契約している人は Claude（追加費用ゼロ）。
契約がない人は Gemini（1人あたり月数百円）。

> **Claude を選ぶ人に必ず伝えること**: 個人向けプラン（Pro / Max）は、
> claude.ai の設定で「モデル改善への利用」が**有効だと入力内容が学習に使われます**。
> 応募者の書類を扱うため、<https://claude.ai/settings/data-privacy-controls> で
> **オフになっていることを確認**してもらってください。
> Team / Enterprise は既定でオフのため確認不要です。

### 1. APIキーの方針を決める（Gemini を使う場合）

> **前提の確認**: 会社の **Google Workspace ライセンスでは Gemini API を使えません。**
> Workspace に含まれるのは Gmail・ドキュメント等の画面内 Gemini だけで、API の利用枠は別契約です。
> Workspace のプラン変更やアドオン追加でも API は使えるようになりません。
> **Google Cloud の請求先アカウント（＝カード登録）を別途用意する必要があります。**
> 日本ではクレジット／デビットカードのみ対応で、銀行口座引き落としは使えません。
> （請求書払いは年 $40,000 以上の支出見込みが要件のため、本件は対象外です）


| 方式 | 内容 | 向き不向き |
|---|---|---|
| **各自が自分のキーを取得**（現行方針） | 各社員が自分の Google アカウントで発行 | 誰の利用かを分けやすいが、**全員分の課金設定が必要**。無料枠のまま運用される事故が起きやすい |
| 課金プロジェクトのキーを配布 | 管理者が1本発行して配る | 課金設定が1箇所で済み、無料枠事故が起きない。ただしキー単位の利用按分はできない |

> **どちらでも、課金が有効なプロジェクトのキーであることが必須**です。無料枠のキーは
> 入力内容が学習に利用される規約のため、応募者書類を扱う本ツールでは使えません。
> 各自取得方式にする場合は、**全員に課金設定を必ず案内してください。**

### 2. APIキーの種別を確認する（2026年9月期限）

Gemini API は **2026年9月に Standard キーからのリクエストを拒否**します。

- AI Studio の APIキー画面で「キーのタイプ」列を確認する
- `Standard` のものは、**新規作成して差し替える**（AI Studio で新規作成したキーは自動的に auth key になる）
- 呼び出し方は変わらないため、**ツール側の改修は不要**。キーを差し替えるだけ

### 3. 動作確認

配布用パッケージを作る前に、開発機で動作を確認します。

```powershell
.venv\Scripts\python.exe run.py doctor
```

全項目 `OK` になることを確認してください。

## 配布パッケージの作成

```powershell
powershell -ExecutionPolicy Bypass -File setup\build_dist.ps1
```

`dist\AGS_HRMOS_AUTO_EVAL_YYYYMMDD.zip` が生成されます。

このスクリプトは Git 管理下のファイルを基準に組み立て、次を**自動で除外**します。

| 除外されるもの | 理由 |
|---|---|
| `config.yaml` | HRMOS のパスワードを含む |
| `storage_state.json` | HRMOS のログイン済みセッション（これだけでログインできてしまう） |
| `data/` | 応募者の書類・評価結果・DB |
| `.venv/` | 環境依存のため配布不可 |
| `.claude/` `CLAUDE.md` `docs/package*.json` | 開発用 |

配布に必要なファイルが Git 管理下に無い場合はエラーで停止します（入れ忘れ検知）。

> **新しいファイルを追加したときは `git add` を忘れずに。**未追跡のファイルは zip に入りません。

## 受け渡し方法

| 方法 | MOTW（ブロック） | 備考 |
|---|---|---|
| **社内共有フォルダ・ファイルサーバ** | 付かないことが多い | **推奨** |
| Teams / Slack / メール添付 | **付く** | 受け取る側にブロック解除の案内が必須 |
| ブラウザでダウンロード | **付く** | 同上 |

> **MOTW（Mark of the Web）**＝「他のPCから取得したファイル」という印。これが付いていると
> 展開後の `setup\install.bat` が Windows のセキュリティ警告でブロックされます。
>
> ブラウザ経由で渡す場合は、**必ず「zip を右クリック → プロパティ →『許可する』にチェックしてから展開」**
> を伝えてください。SETUP_GUIDE.html の Step 0 に記載済みです。

配布時に一緒に伝えるもの:

1. zip ファイル
2. [SETUP_GUIDE.html](SETUP_GUIDE.html)（zip に同梱されています）
3. Step 0 のブロック解除が必要かどうか
4. APIキーを配る方式なら、そのキー

## 導入後のフォロー

### 確認してもらうこと

導入した本人に、次を実行して結果を報告してもらいます。

```
.venv\Scripts\python.exe run.py doctor
```

全項目 `OK` なら完了です。

### よくあるつまずき

| 症状 | 対処 |
|---|---|
| 「Python が見つかりません」で止まる | Python 導入直後は PATH が未反映。**画面を閉じて `setup\install.bat` をもう一度**実行してもらう |
| SmartScreen で実行できない | Step 0 のブロック解除。または「詳細情報」→「実行」 |
| APIキーを入れても疎通 NG | 環境変数は既存の画面に反映されない。**新しい画面**で `doctor` を実行してもらう |
| 課金が無効のまま運用されている | `doctor` の疎通行に注意書きが出る。AI Studio の「請求階層」を確認してもらう |

## 運用の設計上の注意

### 1台集約か、全員配布か

同僚全員の PC に入れるのではなく、**1台でスキャンを回して結果のメールと Excel を全員に配る**構成も可能です（`config.yaml` の `email.to` に全員を列挙）。

| | 全員配布 | 1台集約 |
|---|---|---|
| 課金設定 | 人数分 | **1箇所** |
| APIキー管理 | 人数分 | **1本** |
| 導入の手間 | 人数分 | **1回** |
| 単一障害点 | なし | **その1台が止まると全員に影響** |

1台集約にする場合は、その PC のスリープ対策（`setup_scheduler.ps1` が設定済み）と、
`ROADMAP.md` に記載の `WakeToRun` の制約を確認してください。

### やってはいけないこと

- **Claude の1契約を複数人で共有しない**（利用規約で明確に禁止されています）
- **AI の判定だけで足切りしない**（利用規約上、有資格者による事前レビューが要件）
- **`run.py scan --all` を安易に実行しない**（全応募者を再評価するため、HRMOS へ大量アクセスが発生します）
